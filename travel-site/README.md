# موقع حجوزات فنادق مكة — أسس المسافر

موقع عربي (RTL) للحجز أونلاين: بحث بالتواريخ، توفر فعلي للغرف، أسعار شاملة الضريبة، دفع إلكتروني، قسيمة حجز، ولوحة إدارة.

## ماذا يشمل
- **الزوار:** الرئيسية، قائمة الفنادق وصفحة الفندق (صور، المرافق، البعد عن الحرم، إطلالة الكعبة)، الحجز، الدفع، قسيمة قابلة للطباعة (بالتاريخ الهجري)، تتبّع الحجز برقم الجوال، الشروط/الإلغاء/الخصوصية/من نحن، SEO (sitemap, JSON-LD).
- **الإدارة (`/admin`):** الحجوزات وحالاتها، الفنادق والصور، أنواع الغرف وأسعار المواسم (رمضان، الحج…)، الإعدادات، وصفحة «الامتثال» كقائمة تحقق قبل الإطلاق.
- **التوفر:** يُحسب لكل ليلة؛ الحجز غير المدفوع يُحجز مؤقتًا (30 دقيقة افتراضيًا، 24 ساعة للحوالة) ثم يُحرَّر تلقائيًا.

## متطلبات وزارة السياحة والتجارة الإلكترونية (ما يعرضه الموقع)
يعرض في التذييل وعلى القسيمة: **رقم ترخيص وزارة السياحة، السجل التجاري، الرقم الضريبي، توثيق المركز السعودي للأعمال** (من الإعدادات)، مع الأسعار بالريال شاملة 15% ضريبة وتفصيلها قبل الدفع، وصفحات الشروط وسياسة الإلغاء والاسترداد والخصوصية، ووسائل التواصل والعنوان، وموافقة العميل على الشروط قبل الحجز.
> النصوص النظامية الافتراضية **نموذجية** وليست استشارة قانونية؛ راجعها مع مستشار قبل الإطلاق وأكّد المتطلبات الحالية مع الوزارة. أدخل أرقامك الحقيقية فقط من الإعدادات.

## الإشعارات (بريد + واتساب)
عند كل حجز جديد، وعند تأكيد الدفع أو الإلغاء أو اختيار الحوالة، يصل إشعار للوكالة بالبريد وواتساب، ويصل النزيل بريد تأكيد بعد الدفع إن أدخل بريده. تعمل في الخلفية ولا تعطّل الحجز إن فشلت.
- **البريد:** `SMTP_HOST/PORT/USER/PASS` (مثلًا Gmail مع «كلمة مرور التطبيقات»).
- **واتساب:** عبر WhatsApp Cloud API من Meta (`WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`). الرسائل من المنشأة خارج 24 ساعة تحتاج **قالبًا معتمدًا** (`WHATSAPP_TEMPLATE` بخمسة متغيرات: رقم الحجز، الفندق، التواريخ، الإجمالي، النزيل). بدون المفاتيح تبقى الإشعارات بريدًا فقط، ويبقى زر «مراسلة النزيل واتساب» يدويًا في لوحة الإدارة.

## روابط الدفع
الإدارة ← «روابط الدفع»: أنشئ رابطًا بمبلغ وبيان (أو من صفحة الحجز مباشرة بزر «إنشاء رابط دفع»)، وأرسله بزر واتساب. العميل يفتح الرابط ويدفع بمدى/فيزا، ويُتحقق من الدفع من خادم البوابة. الرابط المرتبط بحجز بكامل مبلغه يؤكد الحجز تلقائيًا. للروابط صلاحية (72 ساعة افتراضيًا).

## شعارا وزارة السياحة ووزارة التجارة
ضع الملفين من المصادر الرسمية للوزارتين (الاستخدام حسب أدلة الهوية الرسمية) باسم `public/brand/mot-logo.png` و`public/brand/moc-logo.png`؛ يظهران في التذييل تلقائيًا. لم أستطع تنزيلهما من بيئة التطوير.

## الربط مع المركز السعودي للأعمال
بعد توثيق متجرك في المركز، ضع **رقم/معرّف التوثيق** و**رابط صفحته** في الإعدادات فيظهر في التذييل. (العرض فقط؛ لا يوجد ربط برمجي آلي.)

## التشغيل محليًا
```bash
cd travel-site && npm install
ADMIN_PASSWORD=تجربة-12345678 MOCK_PAYMENTS=1 npm start     # http://localhost:3000
npm run seed:demo   # بيانات وهمية للمعاينة فقط — لا تشغّله على الموقع الحقيقي
npm test            # اختبار شامل للرحلة والأمان
```
`MOCK_PAYMENTS=1` بوابة وهمية للتجربة؛ تُعطَّل تلقائيًا مع `NODE_ENV=production`.

## بوابات الدفع
المفاتيح **في متغيرات البيئة فقط** (لا تُخزَّن في القاعدة ولا تظهر في الواجهة). تظهر البوابة تلقائيًا عند ضبط مفتاحها:

| البوابة | المتغيرات |
|---|---|
| ميسر Moyasar | `MOYASAR_SECRET_KEY` |
| تاب Tap | `TAP_SECRET_KEY` |
| باي تابس PayTabs | `PAYTABS_PROFILE_ID` `PAYTABS_SERVER_KEY` (`PAYTABS_BASE_URL` لمنطقتك) |

بالإضافة إلى **الحوالة البنكية** و**ادفع لاحقًا** من الإعدادات. التأكيد يتم بعد التحقق من خادم البوابة وتطابق المبلغ، لا بالثقة بما يرجع من المتصفح.
**إضافة بوابة جديدة** (مثل HyperPay): أضف كائنًا في `PROVIDERS` داخل `lib/payments.js` بثلاث دوال `enabled/create/verify` (انظر الأمثلة).
> ⚠️ تكاملات البوابات مكتوبة حسب توثيقها العام ولم تُجرَّب مع حساباتك؛ جرّب كل بوابة في وضع الـ sandbox بمفاتيح تجريبية ودفعة صغيرة قبل الإطلاق.

## النشر على دومين
**Render:** الخدمة `asas-almusafer` مضافة في `render.yaml` بجذر المستودع (New → Blueprint). عبّئ `ADMIN_PASSWORD` و`WHATSAPP` و`BASE_URL`، ثم من Settings → Custom Domains أضف دومينك وأنشئ سجلات DNS التي يعطيك إياها (شهادة HTTPS تلقائية).
**VPS/أي استضافة Docker:** `docker build -t asas . && docker run -d -p 3000:3000 -v asas-data:/data --env-file .env asas` خلف Caddy/Nginx لـ HTTPS.
نسخ احتياطي: انسخ مجلد `DATA_DIR` (قاعدة `asas.db` + `uploads/`).

## الأمان المطبّق
HTTPS/HSTS وCSP صارمة (بدون سكربتات خارجية)، حماية CSRF، كوكيز HttpOnly وSameSite، تحديد معدل الطلبات والدخول، تهريب كل المخرجات ضد XSS، استعلامات SQL محضّرة، رفع صور مفحوص (النوع + البصمة + الحجم)، حماية بيانات الحجز (كوكي الحجز أو التحقق برقم الجوال)، لا تُخزَّن بيانات البطاقات إطلاقًا، رفض الإقلاع في الإنتاج بكلمة مرور ضعيفة.

## غير مشمول بعد
إشعارات البريد/SMS التلقائية (حاليًا مراسلة الواتساب يدويًا من لوحة الإدارة)، الاسترداد الآلي عبر البوابة (يتم من لوحة البوابة)، تعدد المستخدمين في الإدارة، واجهة إنجليزية.
